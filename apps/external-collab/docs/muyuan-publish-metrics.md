# 示例开发01发布与成单看板取数口径

以下口径用于更新看板静态数据，当前仅针对示例开发01。发布和成单必须分别取数，不能把发布数据复制到成单，也不能通过分项相加反推总业绩。

## 手动目标保留

- 用户已于2026-09-29手动录入示例开发01别名2026年方片月9月发布目标；以后更新发布业绩时必须保留目标，不重置、不覆盖。
- 手动目标保存在浏览器 `localStorage` 的 `dashboard-manual-values` 中，并按人员、看板维度和指标分别保存。更新实绩只修改对应业绩数据，不清空或替换这份手动值；目标金额以用户当前看板保存值为准，不写入业绩常量。

## 一、统一筛选框架

每次更新先确定四个固定条件：

- 年份：2026 年。
- 方片月：本月使用 9 月，上月使用 8 月；必须按方片月考核周期，不按自然月。
- 业绩类型：开发。
- 员工：示例开发01，员工 ID 为 275。

两个看板唯一的核心区别是“数据类型”：

- 发布看板：数据类型选择“发布”。
- 成单看板：数据类型选择“成单”。

目标看板的总业绩、十点半、自孵和各平台签约业绩，都必须在对应的数据类型下重新筛选；成单看板不能沿用发布看板的任何分项。

## 三、发布看板外采口径

发布外采单独来自“订单管理 → 外采订单”，不使用商务看板分项相加：

- 订单类型：外采订单（`order_type=3`）。
- 结款商务：示例开发01（员工 ID 275）。
- 时间字段：结款时间（`payment_time`），按对应完整方片月筛选。
- 有效订单状态：等待发布、等待结款、已结款（`100、200、300`）；排除已取消和草稿。
- 外采业绩：加总订单列表的“公司总收益/公司收益”字段。
- 外采单数：筛选结果的订单数量。

## 六、方片月时间规则

- 2026 年 9 月：`2026-08-23 00:00:00` 至 `2026-09-27 00:00:00`，结束时间不含。
- 2026 年 8 月：`2026-07-26 00:00:00` 至 `2026-08-23 00:00:00`，结束时间不含。
- 更新其他月份时，先查 `docs/fangpian-month-calendar-2026.md` 的周期，不得按自然月推算。
- 订单接口使用半开区间 `[start_date, end_date)`；不要为了“包含最后一天”自行把结束时间再延长。

## 七、后续更新操作清单

1. 先确认要更新的是发布还是成单，不能只切换日期而保留另一种数据类型。
2. 将方片月 9 月作为本月、8 月作为上月；更新其他月份时先查方片月周期表的 `start_date` 和 `end_date`。
3. 总业绩、十点半、自孵、三个平台签约业绩分别从对应看板指标读取，不能通过其他指标相加得到。
4. 发布外采使用 `payment_time`；成单外采使用 `order_date`。两者都使用公司总收益金额和有效状态 `100、200、300`。
5. 更新代码时，发布使用 `MU_YUAN_CURRENT_PERFORMANCE` / `MU_YUAN_LAST_MONTH_PERFORMANCE`，成单使用 `MU_YUAN_DEAL_CURRENT_PERFORMANCE` / `MU_YUAN_DEAL_LAST_MONTH_PERFORMANCE`；不得交叉展开或复用。
6. 只修改用户指定的看板、月份和指标，其他人员及其他看板数据保持不变。

# 示例开发01别名结款看板筛选逻辑（后续更新口径）

适用对象：示例开发01（员工 ID `275`），仅更新示例开发01别名结款看板时使用。

## 统一筛选

- 年份：`2026`。
- 方片月：本月使用方片月 9 月（`month_id=148`），上月使用方片月 8 月（`month_id=147`）；不得按自然月替代。
- 业绩类型：`开发`，对应 `performance_type=develop`。
- 数据类型：`结款`，对应 `revenue_type=settlement`。
- 部门：示例开发10别名组（部门 ID `187`）。
- 员工：示例开发01（`employee_id=275`）。
- 外采标记：商务看板指标使用 `is_foreign_broker=0`；外采指标不从商务看板分项相加，单独按外采订单规则统计。

## 指标取数

- **总业绩**：调用 `/api/admin/statOrderRevenue/getEmployeeRevenue`，平台=全部必须显式传 `platform_id=0`；读取示例开发01员工行的 `revenue`，不能把各平台相加代替总业绩。
- **十点半业绩**：调用 `/api/admin/statOrderRevenue/getSelfGenerateHalfPastTenRevenue`，按 `month_id`、`revenue_type=settlement`、`employee_id=275` 取员工行的 `revenue`。
- **自孵（不包含十点半）业绩**：调用 `/api/admin/statOrderRevenue/getSelfGenerateBusinessEmployeeRevenue`，按 `month_id`、`revenue_type=settlement`、`performance_type=develop`、`employee_id=275` 取员工行的 `revenue`。禁止使用 `getSelfGenerateOrdertypeRevenue` 的 `department_id=187` 行，因为那是示例开发10别名组部门汇总，不是示例开发01别名示例公司有限公司值。
- **签约小红书业绩**：调用 `getEmployeeRevenue`，平台=小红书传 `platform_id=1`，其余结款筛选条件不变。
- **签约抖音业绩**：调用 `getEmployeeRevenue`，平台=抖音传 `platform_id=2`，其余结款筛选条件不变。
- **签约视频号业绩**：调用 `getEmployeeRevenue`，平台=视频号传 `platform_id=5`，其余结款筛选条件不变。
- 商务看板上述指标读取 `employee_revenue` 中 `employee_id=275` 的员工行，金额字段取 `revenue`，订单数字段取 `ordernum`（十点半/自孵接口对应 `order_count`）。

## 外采指标

- 页面路径：订单管理 → 外采订单。
- 订单类型：外采订单，`order_type=3`。
- 结款商务：示例开发01，按结款商务字段筛选员工 ID `275`。
- 时间字段：`payment_time`（结款时间），按对应方片月的完整半开区间 `[start_date, end_date)` 筛选。
- 有效状态：等待发布、等待结款、已结款（`100、200、300`）；排除已取消和草稿。
- 外采业绩：对筛选结果的“公司总收益/公司收益”字段求和。
- 外采单数：筛选结果的订单数量。
- 不得使用成单看板的 `order_date`，也不得沿用发布/成单的外采静态值而不核对月份。

## 示例开发01别名十点半发布业绩订单筛选

### 主口径：在自孵订单中筛选十点半账号

十点半发布业绩按订单管理的自孵发布订单筛选计算；十点半员工统计接口只能用于交叉核对，不能代替订单筛选作为主口径：

- 订单类型：自孵，`order_type=1`。
- 时间字段：发布时间 `publish_time`，按方片月完整半开区间筛选；2026年方片月9月是 `[1787414400,1790438400)`（北京时间 `2026-08-23 00:00:00` 至 `2026-09-27 00:00:00`，结束不含）。不要改用自然月或成单/结款时间。
- 人员归属：商务选择示例开发01（员工 ID `275`）；统计接口使用 `employee_id=275`。订单列表复核时沿用天玑该指标对应的商务筛选项，不要自行在成单商务、结款商务等字段之间替换。
- 订单状态：保留 `100、200、300`（待发布、待结款、已结款），排除草稿、取消订单。
- 十点半账号：以提供的刊例表为底表，按平台及平台账号 ID 匹配；昵称大小写或改名时结合已确认的别名核对。用户已确认小红书“在桃芝士”是“开水白雪”改名后的名称，且“画个小饼（狂测版）”和“帧时髦”也属于十点半账号。订单 `G260916470`、`G260909220`、`G260922335` 是已核实的对应订单示例。
- 对匹配到的十点半账号订单汇总 `order_money`（对应成交金额/`order_money_total`），统计订单数；不要使用公司收益 `income_money`。
- **交叉核对**：可调用 `/api/admin/statOrderRevenue/getSelfGenerateHalfPastTenRevenue`，按 `month_id`、`dept_id=187`、发布、开发、员工 `275`、平台全部、非外采查员工示例公司有限公司行。它用于比对订单筛选结果，不改变订单筛选主口径；此接口不需要额外传 `year_id`。
- 已核对样例：2026年方片月8月为 `5` 单、`49,453.40` 元；9月最新自孵发布订单共 `69` 单、`744,562.72` 元，其中十点半 `40` 单、`368,186.72` 元，自孵（不含十点半）`29` 单、`376,376.00` 元。十点半订单按用户确认将“周七joy”计入；该订单的刊例主页链接ID与天玑平台账号ID不一致。统计接口当前同为40单、`368,186.72` 元，仅作交叉核对。

曾出现按刊例表旧昵称/账号清单仅筛得 `示例品牌,290.72` 元、而天玑专用接口为 `373,384.92` 元的差异；缺少的 `13,094.20` 元正是“在桃芝士”订单。后续更新必须保留该昵称别名，以订单明细按账号筛选并汇总为主口径，天玑统计接口只作交叉核对。
